Create `services/nova-core/app/forgejo.py` — an async Forgejo API client class following the same httpx + token-auth + label-resolution pattern as `services/ops-bridge/app.py` but designed for in-process use from scheduler jobs.

**ForgejoClient class API:**

```
class ForgejoClient:
    def __init__(self, base_url: str, repo: str, token: str) -> None
    async def create_issue(self, title: str, body: str, labels: list[str] | None = None) -> int
    async def comment_issue(self, issue_number: int, body: str) -> None
    async def close_issue(self, issue_number: int) -> None
    async def add_label(self, issue_number: int, label: str) -> None
    async def remove_label(self, issue_number: int, label: str) -> None
    async def open_issues_by_label(self, label: str) -> list[dict]
```

- Internal `_resolve_label_ids` method caches label name→ID mappings (same approach as ops-bridge)
- Internal `_api` helper mirrors ops-bridge's `fapi` pattern: wraps httpx.AsyncClient calls with auth header
- All errors raise `ForgejoError` (custom exception with status code and message)
- Rate limit: add 1-second delay between calls to avoid Forgejo rate limits
- Log all API calls at DEBUG level; log failures at WARNING level

Add to `services/nova-core/app/config.py` — add these new fields to the `Settings` class:

```
forgejo_url: str = "https://git.7rb.nl"

maintenance_dep_check_enabled: bool = True
maintenance_log_anomaly_enabled: bool = True
maintenance_backup_verify_enabled: bool = True
maintenance_trend_report_enabled: bool = True
backup_dump_dir: str = "/backups/postgres"
backup_dump_pattern: str = "nova-*.sql"
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Nova-core container → Forgejo API | Internet HTTPS API — Forgejo token crosses this boundary |
| Nova-core container → Docker socket | Host-level Unix socket — docker.sock mounted ro |
| Nova-core container → OpenObserve API | Local network (Coolify-managed) — query for log anomalies |
| Nova-core container → Postgres | Internal Docker network — backup verification queries |
| Nova-core container → Host filesystem | Mounted volume for backup dumps |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-01 | Spoofing | ForgejoClient | critical | mitigate | Forgejo token sourced from env var only; never logged or serialized; same pattern as ops-bridge app.py FORGEJO_TOKEN handling |
| T-29-02 | Elevation of Privilege | Docker socket mount | critical | mitigate | Socket mounted read-only (ro); only specific docker commands with controlled args; no docker exec with user-controlled input |
| T-29-03 | Tampering | Git branch creation | high | mitigate | Test gate runs before dependency-scanner branch creation; human approval gate on merge (no auto-merge); branch never auto-pushed |
| T-29-04 | Information Disclosure | OpenObserve/Forgejo error output | medium | mitigate | Error handlers redact token and password values from log output; same pattern as existing ops-bridge |
| T-29-05 | Information Disclosure | Backup scratch container | low | accept | Scratch container is ephemeral (removed after SELECT), runs on same Docker network, no external exposure |
| T-29-SC | Tampering | Package install (pip-audit) | high | mitigate | Blocking human checkpoint to verify pip-audit package on pypi.org before install; skip if [SUS] or [SLOP] |
</threat_model>
