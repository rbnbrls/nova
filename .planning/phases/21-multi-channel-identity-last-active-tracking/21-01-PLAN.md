  <name>Task 1: Wrap WhatsApp and Telegram last-active UPDATEs in explicit transactions (D-01)</name>
  <files>
    services/nova-core/app/channels/whatsapp.py
    services/nova-core/app/channels/telegram.py

  <action>
    Both channel handlers already update `last_inbound_at` (on `users`) and `last_active_channel` (on `user_preferences`) — D-01. The two UPDATEs execute in the same `pool.acquire()` connection but are NOT in an explicit transaction (asyncpg auto-commits each statement). Wrap them in `async with conn.transaction():` so they commit or rollback as a single atomic unit.

    **whatsapp.py** (`process_incoming_whatsapp`, lines 343-351):
    Change the existing block from bare `async with pool.acquire() as conn:` to:
    ```python
    async with pool.acquire() as conn:
        async with conn.transaction():
            await conn.execute("UPDATE users SET last_inbound_at = now() WHERE name = $1", user.name)
            await conn.execute(
                "UPDATE user_preferences SET last_active_channel = 'whatsapp' ...",
                user.name
            )
    ```
    Keep the existing `try/except Exception` wrapper around the entire block unchanged — the transaction will roll back on exception, preserving the current error-handling behavior.

    **telegram.py** (`process_incoming_telegram`, lines 269-278):
    Same transformation — wrap the two `conn.execute()` calls in `async with conn.transaction():`.
    The existing `try/except Exception` block already wraps both statements; insert the `async with conn.transaction():` inside the `async with pool.acquire() as conn:` but before the UPDATEs.

    Do NOT modify any other behavior (DND check, agent call, downstream send, etc.).
    Do NOT import anything new — `conn.transaction()` is an asyncpg built-in available on any connection.
  </action>
