<objective>
Wire Do Not Disturb as a single gate in the dispatcher so every proactive send respects per-user quiet hours without duplicating DND logic across channels.

Purpose: `is_user_in_dnd()` exists in identity.py and is called by both WhatsApp and Telegram adapters independently, but the dispatcher (the central routing point) does NOT check DND. This means messages routed via `send_to_user()` bypass DND if they go through a path that doesn't check. Fix: move DND enforcement to the dispatcher so all proactive sends are gated once.

Output:
- `send_to_user()` checks DND before routing and queues suppressed messages with the correct channel
- Individual channel adapters remove their redundant DND checks
- Telegram adapter queues (not just drops) during DND
</objective>

  <action>
    The dispatcher `send_to_user()` in `channels/dispatcher.py` currently routes to the user's last-active channel without checking DND. Concurrently, WhatsApp's `adapter.send_message()` checks DND individually (lines 126-142) and Telegram's `_send_to_chat_id()` also checks DND (lines 219-222). This creates three problems:
    1. DND is checked in three places, each with slightly different queuing behavior
    2. The dispatcher path bypasses DND entirely for any non-WhatsApp channel
    3. Telegram DND drops messages instead of queuing them (SC #3 violation)

    **Fix dispatcher.py — add DND check to `send_to_user()`:**
    After resolving `last_channel` but BEFORE routing to the adapter, add:
    ```python
    from ..identity import is_user_in_dnd
    if proactive:
        in_dnd = await is_user_in_dnd(user_name)
        if in_dnd:
            print(f"[DND ACTIVE] Queuing proactive message for {user_name} (channel: {last_channel})")
            async with pool.acquire() as conn:
                user_id = await conn.fetchval("SELECT id FROM users WHERE name = $1", user_name)
                if user_id:
                    channel_id = None
                    if last_channel == "telegram":
                        channel_id = await conn.fetchval(
                            "SELECT channel_id FROM channel_identities WHERE channel = 'telegram' AND user_id = $1",
                            user_id
                        )
                    elif last_channel == "whatsapp":
                        channel_id = await conn.fetchval(
                            "SELECT whatsapp_number FROM user_preferences WHERE user_id = $1",
                            user_id
                        )
                    await conn.execute(
                        """INSERT INTO queued_notifications (user_id, whatsapp_number, message_text, channel)
                           VALUES ($1, $2, $3, $4)""",
                        user_id, channel_id or "", text, last_channel
                    )
            return
    ```
    The INSERT stores `channel_id` in `whatsapp_number` column (existing schema pattern) and sets `channel` to the resolved `last_channel` — so when `process_queued_notifications` replays, it reads the correct channel.

    **Fix whatsapp.py — remove redundant DND check:**
    In `WhatsAppAdapter.send_message()` (around lines 126-142), remove the DND block entirely:
    ```python
    # Remove this entire block — DND is now enforced in send_to_user():
    # if proactive and user.name != "household":
    #     from ..identity import is_user_in_dnd
    #     if await is_user_in_dnd(user.name):
    #         print(f"[DND ACTIVE] Queuing proactive message...")
    #         ... (remove this block)
    ```
    Replace it with a brief comment:
    ```python
    # DND check: handled upstream in dispatcher.send_to_user()
    ```
    Do NOT change any other logic. The `send_message` function still handles 24h compliance window and mock mode.

    **Fix telegram.py — `_send_to_chat_id` DND behavior:**
    In `_send_to_chat_id()` (around lines 219-222), the current behavior drops proactive messages during DND:
    ```python
    if proactive and user.name != "household":
        if await is_user_in_dnd(user.name):
            print(f"[DND ACTIVE] Suppressing Telegram proactive message for {user.name} ({chat_id})")
            return  # <-- silently drops, no queue
    ```
    Remove the silent-drop `return` and replace with a queuing path:
    ```python
    if proactive and user.name != "household":
        if await is_user_in_dnd(user.name):
            print(f"[DND ACTIVE] Queuing Telegram proactive message for {user.name} ({chat_id})")
            pool = await get_pool()
            async with pool.acquire() as conn:
                user_id = await conn.fetchval("SELECT id FROM users WHERE name = $1", user.name)
                if user_id:
                    await conn.execute(
                        """INSERT INTO queued_notifications (user_id, whatsapp_number, message_text, channel)
                           VALUES ($1, $2, $3, 'telegram')""",
                        user_id, chat_id, text
                    )
            return
    ```
    This ensures Telegram proactive messages are queued (not dropped) during DND, and the `channel='telegram'` value matches what `process_queued_notifications()` expects.

    **Why keep the DND check in `_send_to_chat_id` at all?**
    Because `_send_to_chat_id` is also called directly by `send_telegram_message(chat_id, text, proactive=True)` from places that bypass the dispatcher (e.g. legacy code paths). Until all call sites migrate to the dispatcher, the check provides defense in depth. Once migration is complete, this check can be removed in a future cleanup phase.

    Do NOT modify `is_user_in_dnd()` in identity.py — it already handles overnight windows and error cases correctly.
    Do NOT modify `process_queued_notifications()` in scheduler.py — it already reads the `channel` column and routes to the correct adapter.
