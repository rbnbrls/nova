    ```python
    @app.get("/dashboard/audit")
    async def dashboard_audit(limit: int = 50) -> dict:
        pool = await db.get_pool()
        async with pool.acquire() as conn:
            rows = await conn.fetch(
                """
                SELECT id, created_at, user_name, tool_name, action_summary, status, confirmation_required
                FROM audit_log
                WHERE created_at > now() - interval '90 days'
                ORDER BY created_at DESC
                LIMIT $1
                """,
                limit,
            )
        entries = []
        for r in rows:
            entries.append({
                "id": r["id"],
                "timestamp": r["created_at"].isoformat(),
                "user_name": r["user_name"],
                "tool_name": r["tool_name"],
                "action_summary": r["action_summary"],
                "status": r["status"],
                "confirmation_required": r["confirmation_required"],
            })
        return {"audit": entries}
    ```

    Add a new function `updateAudit(entries)`:

    ```javascript
    function updateAudit(entries) {
        const container = document.getElementById('audit-content');
        const countBadge = document.getElementById('audit-count');

        if (!entries || entries.length === 0) {
            container.innerHTML = '<div class="placeholder-loader">No recent activity.</div>';
            countBadge.textContent = '0';
            return;
        }

        countBadge.textContent = entries.length;

        let html = '<table class="audit-table"><thead><tr><th>Time</th><th>User</th><th>Action</th><th>Status</th></tr></thead><tbody>';
        entries.forEach(entry => {
            const ts = entry.timestamp ? new Date(entry.timestamp) : new Date();
            const timeStr = ts.toLocaleTimeString([], { hour: '2-digit', minute: '2-digit', month: 'short', day: 'numeric' });
            const statusClass = entry.status === 'denied' ? 'status-denied' : 'status-completed';
            const statusLabel = entry.status === 'denied' ? '🚫 Denied' : '✅ Done';
            const confirmIcon = entry.confirmation_required ? '🛡️ ' : '';
            html += `<tr>
                <td class="audit-time">${timeStr}</td>
                <td class="audit-user">${entry.user_name || 'system'}</td>
                <td class="audit-action">${confirmIcon}${escapeHtml(entry.action_summary)}</td>
                <td class="audit-status"><span class="${statusClass}">${statusLabel}</span></td>
            </tr>`;
        });
        html += '</tbody></table>';
        container.innerHTML = html;
    }

    function escapeHtml(text) {
        const div = document.createElement('div');
        div.textContent = text;
        return div.innerHTML;
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API consumer → FastAPI | The dashboard and /dashboard/audit endpoint are LAN-only, same as existing dashboard (Phase 12). No external auth on these endpoints. |
| Agent loop → audit_log | The agent writes to audit_log after every mutating tool call. The write path uses parameterized queries (asyncpg) — no SQL injection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-36-01 | Spoofing | audit_log INSERT (agent.py) | Low | Accept | The `user_name` field records the resolved user from the agent loop (already authenticated before reaching run_agent). Impersonation would require compromising the agent loop itself, which is out of scope for this phase. |
| T-36-02 | Tampering | audit_log rows | Low | Accept | Direct DB access could modify rows, but this requires Postgres credentials at the LAN level — same trust model as all other tables. No additional hardening needed. |
| T-36-03 | Information Disclosure | /dashboard/audit endpoint | Low | Accept | The dashboard endpoints have no auth (inherited from Phase 12 design). Audit data is household-internal only. LAN-only deployment means no external exposure. |
| T-36-04 | Denial of Service | audit_log table growth | Low | Mitigate | 90-day WHERE filter in the endpoint + auto-prune at query time. Rapid tool calls during agent loops are bounded by nova_max_iterations (default 6). Even at max rate the row count is small. |
</threat_model>
