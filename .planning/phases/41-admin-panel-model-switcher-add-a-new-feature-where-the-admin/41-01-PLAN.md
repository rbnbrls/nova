    In `services/nova-core/app/config.py`, append AFTER the `settings = Settings()` line:

    ```python
    # --- Runtime-persistent config (Phase 41 — app_config DB table) ---
    # Module-level cache; re-reads from DB on each call. Writes are infrequent
    # and happen via the same process, so TTL is unnecessary.
    # TODO: Extend with active_embed_model, active_vision_model in future phases.
    _active_model_override: str | None = None

    async def get_active_model() -> str:
        \"\"\"Return active model from app_config, falling back to env default.\"\"\"
        if _active_model_override:
            return _active_model_override
        try:
            pool = await db.get_pool()
            async with pool.acquire() as conn:
                row = await conn.fetchrow(
                    "SELECT value FROM app_config WHERE key = 'active_model'"
                )
                if row and row["value"]:
                    _active_model_override = row["value"]
                    return row["value"]
        except Exception:
            log.warning("Failed to read active_model from DB, using env default")
        return settings.nova_model

    async def set_active_model(model: str) -> None:
        \"\"\"Persist active model to app_config (upsert).\"\"\"
        global _active_model_override
        pool = await db.get_pool()
        async with pool.acquire() as conn:
            await conn.execute(
                """
                INSERT INTO app_config (key, value) VALUES ('active_model', $1)
                ON CONFLICT (key) DO UPDATE
                SET value = EXCLUDED.value, updated_at = now()
                """,
                model,
            )
        _active_model_override = model

    def get_active_model_sync() -> str:
        \"\"\"Synchronous getter for places that cannot use await.
        Falls back to env default if override hasn't been loaded yet.\"\"\"
        return _active_model_override or settings.nova_model
    ```

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-41-01 | Tampering | admin_models.py pull_model / delete_model — model name injection | high | mitigate | Validate model names with regex `^[a-zA-Z0-9:_\-./]+$` in all proxy functions — reject at the endpoint layer (enforced in Wave 1 endpoints). The proxy functions accept strings; the regex gate lives in main.py POST handlers. |
| T-41-02 | Denial of Service | admin_models.py pull_model — resource exhaustion from multiple pulls | high | mitigate | `_pull_lock` enforces one concurrent pull. A second pull request while one is active returns 409 "A pull is already in progress" (enforced in Wave 1 endpoint). |
| T-41-03 | Denial of Service | admin_models.py pull_model — disk exhaustion from large model download | low | accept | No disk-space monitoring in this phase. Household users understand their hardware limits (accepted risk per RESEARCH.md). |
| T-41-04 | Information Disclosure | admin_models.py — Ollama API error tracebacks leaking internal paths | medium | mitigate | All Ollama API proxy functions catch httpx.HTTPError and httpx.RequestError, return structured dicts with safe messages. Never expose tracebacks, raw response text, or internal paths. |
| T-41-05 | Spoofing | admin_models.py load_model — unload of active model during agent loop | medium | mitigate | `set_active_model()` is called before `load_model()` new one. If new model fails to load, the old model is restored (rollback pattern in RESEARCH.md). The old model unload is fire-and-forget. |
</threat_model>
