<objective>
What this plan accomplishes: Add the canonical household planning schema and contact/address-book tables to the Nova database, with supporting CRUD modules and task-tool updates.

Purpose: This is the foundational data-model phase for the entire Household Motion Replacement milestone. Without these schema changes, subsequent phases (auto-scheduler, replanning, task intelligence, CardDAV) have no place to store planning intent, scheduling windows, dependencies, or contacts. The new columns on tasks turn them from flat to-do items into first-class planning objects with duration, windows, deadlines, labels, templates, and dependency relationships. The contact tables give the household a shared address book independent of Nova's internal user table.

Output:
- `alembic/versions/0013_planning_metadata.py` — additive migration adding planning columns to `tasks`, creating `task_dependencies` join table, and creating the five contact/address-book tables
- `app/contacts.py` — new module with asyncpg-based CRUD for contacts (create, read, list, update, delete) and sub-entity management (emails, phones, addresses)
- `app/models.py` — Pydantic models for contact request/response schemas
- `app/tools/tasks.py` — updated `add_task`, `list_tasks`, `complete_task` with planning metadata parameters and dependency handling
</objective>

    New module for contact CRUD operations. Follow the asyncpg pattern from `app/db.py` (get_pool, acquire connection, fetch/fetchrow/execute).

    Module docstring: `"""Contact repository — shared household address book, independent of Nova user table."""`

    Imports:
    - `from __future__ import annotations`
    - `from uuid import UUID`
    - `from datetime import datetime`
    - `from .db import get_pool`

    Functions — each is an async def that acquires the pool and runs queries. All use `$1`, `$2` parameterized queries (never f-string interpolation in SQL).

    **1. `async def create_contact(name: str, notes: str | None = None) -> dict | None`**
    INSERT INTO contacts (name, notes) VALUES ($1, $2) RETURNING id, name, notes, created_at, updated_at. Return the row as a dict, or None on failure.

    **2. `async def get_contact(contact_id: str | UUID) -> dict | None`**
    SELECT c.id, c.name, c.notes, c.created_at, c.updated_at,
           COALESCE(json_agg(DISTINCT jsonb_build_object('id', ce.id, 'email', ce.email, 'type', ce.type)) FILTER (WHERE ce.id IS NOT NULL), '[]') AS emails,
           COALESCE(json_agg(DISTINCT jsonb_build_object('id', cp.id, 'phone', cp.phone, 'type', cp.type)) FILTER (WHERE cp.id IS NOT NULL), '[]') AS phones,
           COALESCE(json_agg(DISTINCT jsonb_build_object('id', ca.id, 'address', ca.address, 'type', ca.type)) FILTER (WHERE ca.id IS NOT NULL), '[]') AS addresses
    FROM contacts c
    LEFT JOIN contact_emails ce ON ce.contact_id = c.id
    LEFT JOIN contact_phones cp ON cp.contact_id = c.id
    LEFT JOIN contact_addresses ca ON ca.contact_id = c.id
    WHERE c.id = $1::uuid
    GROUP BY c.id

    Return the row as a dict, or None. This single query eagerly loads all sub-entities.

    **3. `async def list_contacts(search: str | None = None) -> list[dict]`**
    If search is provided: `SELECT id, name, notes, created_at, updated_at FROM contacts WHERE name ILIKE $1 ORDER BY name ASC` with param `f"%{search}%"`. Otherwise: `SELECT id, name, notes, created_at, updated_at FROM contacts ORDER BY name ASC`.
    Return `[dict(row) for row in rows]`.

    **4. `async def update_contact(contact_id: str | UUID, name: str | None = None, notes: str | None = None) -> dict | None`**
    Build dynamic UPDATE. If neither name nor notes, return current row via get_contact. Otherwise: `UPDATE contacts SET name = COALESCE($1, name), notes = COALESCE($2, notes), updated_at = now() WHERE id = $3::uuid RETURNING id, name, notes, created_at, updated_at`. Only set non-None params. Return updated row dict.

    **5. `async def delete_contact(contact_id: str | UUID) -> bool`**
    `DELETE FROM contacts WHERE id = $1::uuid`. Return `res != "DELETE 0"`.

    **6. `async def add_email(contact_id: str | UUID, email: str, type: str | None = None) -> dict`**
    INSERT INTO contact_emails (contact_id, email, type) VALUES ($1::uuid, $2, $3) RETURNING id, contact_id, email, type. Return row dict.

    **7. `async def add_phone(contact_id: str | UUID, phone: str, type: str | None = None) -> dict`**
    INSERT INTO contact_phones (contact_id, phone, type) VALUES ($1::uuid, $2, $3) RETURNING id, contact_id, phone, type. Return row dict.

    **8. `async def add_address(contact_id: str | UUID, address: str, type: str | None = None) -> dict`**
    INSERT INTO contact_addresses (contact_id, address, type) VALUES ($1::uuid, $2, $3) RETURNING id, contact_id, address, type. Return row dict.

    **9. `async def remove_email(email_id: str | UUID) -> bool`**
    DELETE FROM contact_emails WHERE id = $1::uuid. Return `res != "DELETE 0"`.

    **10. `async def remove_phone(phone_id: str | UUID) -> bool`**
    DELETE FROM contact_phones WHERE id = $1::uuid. Return `res != "DELETE 0"`.

    **11. `async def remove_address(address_id: str | UUID) -> bool`**
    DELETE FROM contact_addresses WHERE id = $1::uuid. Return `res != "DELETE 0"`.
