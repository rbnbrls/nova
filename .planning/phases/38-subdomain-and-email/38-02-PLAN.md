<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Nova → IMAP Server | Nova authenticates to external IMAP server over SSL; untrusted email content enters system |
| Nova → SMTP Server | Nova authenticates to external SMTP relay over TLS; outbound email content exits system |
| LLM → email content | Untrusted email body/subject/sender fed to LLM for classification/extraction/reply |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-38-03 | Information Disclosure | email.py / _get_imap_connection | medium | mitigate | IMAP/SMTP passwords never logged; exceptions catch and log generic messages only (no credential echo); DEBUG-level IMAP tracing disabled via nova_log_level |
| T-38-04 | Tampering | email.py / send_email_message | medium | mitigate | EmailMessage (stdlib) handles RFC-compliant header encoding; send_email tool accepts only to/subject/body params validated by JSON Schema — no raw header injection vector |
| T-38-05 | Tampering | email.py / fetch_emails_imap | low | mitigate | IMAP search criteria are hardcoded strings ("UNSEEN", "UNKEYWORD NovaProcessed") — no user-controlled input reaches IMAP commands |
| T-38-06 | Information Disclosure / Spoofing | email.py / IMAP + SMTP connections | high | mitigate | TLS enforced: IMAP on SSL port 993 (nova_imap_use_ssl=True), SMTP STARTTLS on port 587 (nova_smtp_use_tls=True); aioimaplib/aiosmtplib use Python SSL with certificate validation |
| T-38-07 | Repudiation | email.py / IMAP flag dedup | low | accept | If a processed flag is cleared externally (webmail client), Nova will re-process the email — acceptable for a household assistant; IMAP flags are server-authoritative and the flag is re-set on each processing cycle |
| T-38-08 | Elevation of Privilege | email.py / LLM call chain | low | accept | classify_importance/extract_actions use LLM on untrusted email content — prompt injection risk is inherent to LLM-based email processing; the LLM runs locally with no external API access; actions extracted from email require user confirmation via existing confirmation gate |
</threat_model>
