<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent loop → Ollama API | HTTP requests across network; transient failures (connection refused, 5xx) trigger bounded retry |
| Config → Agent loop | `nova_max_turn_timeout` is an env-config value read at runtime; misuse is operator error, not an attack vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-01 | Denial of Service | llm.chat() retry loop | low | mitigate | Retry count is bounded to 3; even in worst case (3 × 20s HTTP timeout per call across 6 iterations), the 120s wall-clock budget in agent.py caps total turn time. No new unbounded loops introduced. |
| T-17-02 | Information Disclosure | Retry logging in llm.chat() | low | accept | Error messages from Ollama may include internal paths or model metadata. Logs are local-only (stdout/file) with no network egress in this phase. Same risk profile as existing logging across the app. |
| T-17-03 | Tampering | nova_max_turn_timeout config | low | accept | Admin-set env var; no input validation needed. Too-low values cause premature timeouts (user retries), too-high values degrade UX — neither is a security breach. Sensible default (120s) minimizes misconfig risk. |
</threat_model>
