    5. Generate a 6-digit code via `secrets.randbelow(900000) + 100000`, formatted as string.
    6. Set `expires_at = datetime.now(timezone.utc) + timedelta(minutes=5)` (D-05).
    7. Insert into `channel_verification_codes` (user_id, whatsapp_number, code, expires_at, channel='whatsapp').
    8. Call the new `send_whatsapp_otp` function from Task 1. If it raises (Meta API error per D-09), catch the exception, raise HTTP 502 with a detail message like "Failed to send verification code. Please try again." so the UI can show a retry button.

    1. Look up the user by `name` (404 if not found).
    2. Fetch the most recent active verification code row from `channel_verification_codes` for this user where `channel='whatsapp'`, `attempts < 3`, and `expires_at > now()`. ORDER BY `created_at DESC LIMIT 1`. If no row, raise 400 with "No active verification code found. Please request a new code."
    3. Increment `attempts` by 1 immediately (D-11 — always counts toward limit regardless of outcome).
    4. Compare the submitted code against the stored code. If mismatch, raise 400. The error message should inform the user how many attempts remain: "Incorrect code. X attempts remaining." If `attempts + 1 >= 3` after increment, expire the code immediately: "Incorrect code. No attempts remaining. Please request a new code."
    5. On correct code (D-05 — single-use): update `user_preferences.whatsapp_number` to the code's `whatsapp_number` using the existing pattern:
       ```python
       INSERT INTO user_preferences (user_id, whatsapp_number)
       VALUES ($1, $2)
       ON CONFLICT (user_id) DO UPDATE SET whatsapp_number = EXCLUDED.whatsapp_number
       ```
       This handles both first-time linking (INSERT) and re-linking/swap (UPDATE per D-08 — the old number is freed because we just overwrite it on the same user_id row).
    6. Mark the code as consumed: `UPDATE channel_verification_codes SET attempts = 99 WHERE id = $1`.
    7. Return `{"status": "success", "linked_number": row["whatsapp_number"]}`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dashboard browser → Nova Core API | LAN-only, but accepts untrusted user input (phone number, code) |
| Nova Core → Meta Graph API | Outbound HTTPS call to external API for OTP delivery |
| Meta → User phone | OTP code delivered to the claimed phone number via WhatsApp |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Spoofing | POST /dashboard/link-whatsapp/verify | high | mitigate | Rate-limit: 3 max attempts per code, codes expire after 5 min, 1 code per number per 5 min |
| T-14-02 | Tampering | send_whatsapp_otp → Meta API | medium | mitigate | HTTPS only; Meta API uses TLS; the AUTHENTICATION template is Meta-managed |
| T-14-03 | Information Disclosure | Server-side code logging | low | accept | Code is logged for debugging; only accessible to admin with server access |
| T-14-04 | Information Disclosure | OTP in server response | low | mitigate | Endpoints never return the code in response bodies |
| T-14-05 | Denial of Service | POST /dashboard/link-whatsapp/start | medium | mitigate | Rate-limit: 1 code per phone number per 5 min prevents flooding |
| T-14-06 | Elevation of Privilege | POST /dashboard/link-whatsapp/start | high | mitigate | Claim-conflict check prevents linking a number already assigned to another user; UNIQUE constraint on user_preferences.whatsapp_number enforces at DB level |
| T-14-07 | Spoofing | Brute-force code via /verify | high | mitigate | attempts counter + expiry: after 3 wrong guesses the code is consumed (attempts=99), preventing further attempts |
| T-14-08 | Tampering | Re-linking race condition | low | accept | 5-min window + household-of-2 context makes race negligible; UNIQUE constraint prevents DB corruption |
| T-14-SC | Tampering | httpx client install (send_whatsapp_otp) | medium | mitigate | httpx already in project dependencies from Phase 9; no new packages required per D-16 |
</threat_model>
