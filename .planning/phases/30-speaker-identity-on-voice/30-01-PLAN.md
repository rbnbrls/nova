    1. **RoomSessionManager** -- Create `app/voice_rooms.py` with: (D-08 — active user session per room with TTL, falls back to room default)
       - A frozen `@dataclass` class `RoomSession` with fields: `room_id: str`, `active_user: str | None`, `last_activity: datetime`.
       - A class `RoomSessionManager`:
         - `__init__(self, pool: asyncpg.Pool, ttl_minutes: int = 30)`
         - Stores `_sessions: dict[str, RoomSession]` (keyed by `room_id`).
         - `async def get_active_user(self, room_id: str) -> str`:
           - Return cached active_user if session exists and not expired (check `last_activity + ttl > now()`).
           - If expired or no session: query DB `SELECT u.name FROM voice_room_defaults vrd JOIN users u ON vrd.default_user_id = u.id WHERE vrd.room_id = $1`.
           - Fallback chain: active session user -> DB default user -> "household".
           - Create/refresh / expire sessions as appropriate.
           - Use `asyncpg.Pool.acquire()` for the DB lookup, matching the pattern in `identity.py` `user_from_whatsapp()`.
         - `async def set_active_user(self, room_id: str, user_name: str) -> None`:
           - Set `active_user` to user_name, update `last_activity` to now.
           - Create session entry if one doesn't exist for this room_id.
         - `def clear_expired(self) -> int` (sync -- called from scheduler):
           - Remove all sessions where `last_activity + ttl < datetime.now()`.
           - Return count of removed sessions for logging.
           - Guard with early return if `len(self._sessions) == 0`.
       - Import pattern: `from datetime import datetime, timedelta` and `from .db import get_pool`.

    2. **Wire into app lifespan** -- In `app/main.py`:
       - Import `RoomSessionManager` from `.voice_rooms` (add at the top with other imports).

       - Register a scheduler job: `scheduler.add_job(voice_room_manager.clear_expired, "interval", minutes=5, id="voice_room_cleanup")` -- add this right after the existing scheduler job registrations.
       - The manager instance is module-level so endpoint handlers can import it (same pattern as `scheduler` on line 41 of main.py).

    **Consistency note:** Use module-level singleton pattern matching `scheduler` and `_pool` in existing code. The manager is initialized during lifespan, not at import time, because it needs the async pool.
