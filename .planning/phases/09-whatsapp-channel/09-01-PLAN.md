<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WhatsApp Meta → Nova webhook | Inbound HTTPS from Meta's servers to POST /webhooks/whatsapp — the webhook handler receives unvalidated payloads. Signature verification is the sole trust gate. |
| Nova → Meta Cloud API | Outbound HTTPS to graph.facebook.com carrying the WhatsApp access token in the Authorization header. The token is configured via env var and never exposed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|----------|----------|-------------|-----------------|
| T-09-01 | Spoofing | POST /webhooks/whatsapp | critical | mitigate | `verify_whatsapp_signature` HMAC-SHA256 with `hmac.compare_digest` (constant-time). Tests in Task 1 (raw-body, missing header, invalid sig) verify correctness. |
| T-09-02 | Repudiation | Webhook payload replay | medium | accept | No nonce/timestamp tracking in current implementation. Phase 18 (Security Hardening) addresses this. |
| T-09-03 | Spoofing | Identity resolution | high | mitigate | DB-backed identity resolution (`user_from_whatsapp`) with HOUSEHOLD fallback on error. Tests in Task 2 (DB-unavailable path, malformed config) verify fallback. |
| T-09-04 | Information Disclosure | Outbound message routing | medium | mitigate | `send_whatsapp_message` resolves recipient from identity lookup, not from user-controlled input. Tests in Task 3 verify correct routing. |
</threat_model>
