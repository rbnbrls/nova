  <action>
    The old `/api/preferences/request-code` endpoint (around line 757) sends Telegram OTPs via the dispatcher:
    ```python
    if req.channel == "telegram":
        from .channels.dispatcher import send_to_user
        try:
            await send_to_user(req.user, otp_message, proactive=False)
        except Exception as e:
            print(f"[ERROR] Failed to send Telegram OTP to {req.user}: {e}")
    ```
    The problem: `send_to_user()` routes by `last_active_channel`. If the user's `last_active_channel` is `'whatsapp'`, the OTP goes to WhatsApp instead of Telegram, defeating the purpose of Telegram-specific OTP delivery.

    Fix: Replace the `send_to_user` path with a direct call to `send_telegram_otp`:
    ```python
    if req.channel == "telegram":
        try:
            sent = await send_telegram_otp(req.user, code)
            if not sent:
                raise RuntimeError("No chat_id found")
        except Exception as e:
            print(f"[ERROR] Failed to send Telegram OTP to {req.user}: {e}")
            raise HTTPException(
                status_code=502,
                detail="Failed to send verification code via Telegram. Please try again."
            )
    ```

    Key details:
    - `send_telegram_otp()` is already imported at line 33: `from .channels.telegram import ... send_telegram_otp`
    - It resolves `user_name` to `chat_id` via `channel_identities` and sends directly via the Telegram Bot API
    - If `send_telegram_otp` returns `False` (no chat_id found), raise an HTTP 502 with a retry message
    - The `code` variable is already defined at line 739: `code = f"{secrets.randbelow(900000) + 100000}"`
    
    Do NOT modify the WhatsApp branch (`else:` block at line 763) — it correctly uses `send_whatsapp_message(clean_number, otp_message)`.
    Do NOT modify the `/dashboard/link-telegram/*` endpoints — they already use `send_telegram_otp` correctly.
    Do NOT remove the `from .channels.dispatcher import send_to_user` import if it's used elsewhere — only change the call site.

    If `send_to_user` is no longer used anywhere in `request_code` after this change, and is only imported for this one line, you may remove the import.
