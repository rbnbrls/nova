    Refactor `app/db.py` `run_migrations()` to use Alembic for schema management while preserving the data-seeding logic.

    **What stays in `run_migrations()`:**
    - Alembic upgrade call (schema)
    - User preference seeding from `NOVA_WHATSAPP_USERS` env var (lines 71-93)
    - Telegram chat_id seeding from `NOVA_TELEGRAM_USERS` env var (lines 182-205)

    **What is REMOVED from `run_migrations()`:**
    - All raw `conn.execute()` calls that create/alter tables, columns, indexes (lines 25-179 excluding the seeding blocks). These are now managed by Alembic migration `0001_initial_schema.py`.

    **Structure of refactored `run_migrations()`:**

    ```python
    async def run_migrations():
        """Apply pending Alembic migrations, then seed reference data."""
        from alembic.config import Config
        from alembic.command import upgrade

        alembic_cfg = Config(os.path.join(os.path.dirname(__file__), "..", "alembic.ini"))
        alembic_cfg.set_main_option("sqlalchemy.url", settings.database_url)
        upgrade(alembic_cfg, "head")

        pool = await get_pool()
        async with pool.acquire() as conn:
            # Seed user_preferences from NOVA_WHATSAPP_USERS
            if settings.nova_whatsapp_users:
                for entry in settings.nova_whatsapp_users.split(","):
                    entry = entry.strip()
                    if not entry or ":" not in entry:
                        continue
                    number, name = entry.split(":", 1)
                    number = number.strip().lstrip("+")
                    name = name.strip()
                    user_id = await conn.fetchval("SELECT id FROM users WHERE name = $1", name)
                    if user_id:
                        pref_exists = await conn.fetchval(
                            "SELECT 1 FROM user_preferences WHERE user_id = $1", user_id
                        )
                        if not pref_exists:
                            await conn.execute(
                                """
                                INSERT INTO user_preferences (user_id, whatsapp_number)
                                VALUES ($1, $2)
                                ON CONFLICT (whatsapp_number) DO NOTHING
                                """,
                                user_id, number
                            )

            # Seed Telegram channel_identities from NOVA_TELEGRAM_USERS
            if settings.nova_telegram_users:
                for entry in settings.nova_telegram_users.split(","):
                    entry = entry.strip()
                    if not entry or ":" not in entry:
                        continue
                    chat_id, name = entry.split(":", 1)
                    chat_id = chat_id.strip()
                    name = name.strip()
                    user_id = await conn.fetchval("SELECT id FROM users WHERE name = $1", name)
                    if user_id:
                        exists = await conn.fetchval(
                            "SELECT 1 FROM channel_identities WHERE channel = 'telegram' AND channel_id = $1",
                            chat_id
                        )
                        if not exists:
                            await conn.execute(
                                """
                                INSERT INTO channel_identities (user_id, channel, channel_id)
                                VALUES ($1, 'telegram', $2)
                                ON CONFLICT (channel, channel_id) DO NOTHING
                                """,
                                user_id, chat_id
                            )
    ```

    **Alembic config path resolution:** The Alembic config (`alembic.ini`) lives at `services/nova-core/alembic.ini`. From `app/db.py` (at `services/nova-core/app/db.py`), the relative path is `os.path.join(os.path.dirname(__file__), "..", "alembic.ini")`. Use `os.path.abspath()` or `os.path.normpath()` to ensure a clean absolute path before passing to `Config()`.

    **`set_main_option` override:** The Alembic `env.py` reads `sqlalchemy.url` from the config object, not from the INI file on disk. `Config.set_main_option("sqlalchemy.url", settings.database_url)` injects the runtime URL so the INI file never contains credentials.

    **Imports to add** at the top of `app/db.py`: `import os` (for path resolution), `from alembic.config import Config`, `from alembic.command import upgrade`.

    **Sync-to-async bridge:** `alembic.command.upgrade()` is a synchronous call. Running it inside an async function is fine here because:
    - It runs during app startup (in the `lifespan` context manager), not in a request handler
    - The sync call blocks the event loop briefly, but migrations complete in under a second for this schema size
    - Using `asyncio.to_thread()` for the call would add unnecessary complexity for no measurable benefit

    Do NOT include any inline DDL in this module. Do NOT keep `CREATE TABLE IF NOT EXISTS` or `ALTER TABLE ADD COLUMN IF NOT EXISTS` calls. Every schema change must be an Alembic revision.

    Keep the `get_pool()` and `close_pool()` functions unchanged (per D-02: keep-existing-pool-pattern).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| alembic migration scripts to database | Migration code (checked into git) has DDL access to the entire Postgres schema |
| app startup to db.run_migrations() | Raw SQL (data seeding) executes against Postgres before the lifespan completes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | alembic/versions/*.py | medium | mitigate | Migration scripts are source-controlled and code-reviewed (same process as all source code). Destructive operations (DROP, ALTER DROP) are caught in review per the additive-only policy. |
| T-03-02 | Information Disclosure | app.config.settings.database_url | high | mitigate | Database credentials are loaded from environment variables only (SettingsConfigDict(env_file=".env")). alembic.ini does not contain credentials — they are injected at runtime via env.py reading settings.database_url. Never committed to git. |
| T-03-03 | Denial of Service | alembic.command.upgrade() in run_migrations() | medium | mitigate | If the database is unreachable during migration, alembic raises an exception that propagates through db.run_migrations() and is handled by FastAPI lifespan — the app fails to start cleanly. This is correct behavior (fail-fast on schema mismatch). Runbook: check postgres health, verify credentials, run alembic upgrade head manually. |
| T-03-04 | Elevation of Privilege | data seeding SQL (INSERT INTO user_preferences, channel_identities) | low | accept | Data seeding inserts reference data from env-var configuration. Only admin-controlled env vars (NOVA_WHATSAPP_USERS, NOVA_TELEGRAM_USERS) influence what gets seeded. Malicious env var values could insert arbitrary rows, but this requires shell access to the environment — at which point the attacker already controls the container. |
| T-03-SC | Tampering | alembic, psycopg2-binary pip installs | high | mitigate | New packages added to requirements.txt. Both are well-established (alembic: 1B+ downloads, psycopg2-binary: 500M+ downloads). No [SUS] or [SLOP] indicators. Standard pip install from PyPI is sufficient. |
</threat_model>
